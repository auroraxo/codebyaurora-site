Your execution list is a wall of green. Is it true?

n8n reports what the engine did, not what your business did. A run can finish green while the message never sent, the row never wrote, or the branch never fired — and you find out days later, from a client. greenscan is a one-shot, read-only audit that reads your instance's workflows and recent executions and hands you a one-page report of the six failure classes the n8n community has actually named.

A hard_error

Recent executions that threw. n8n's Error Workflow already catches these — flagged only when many.

B missed_run

An active scheduled workflow whose last execution is older than your window.

C early_end

A green execution that stopped before the workflow's last node — the classic "ran, didn't finish".

D empty_output

Successful runs producing zero items, at ≥50% of a workflow's recent successes (n≥5, so small samples don't lie).

E coaf_risk

A node with both onError: continueRegularOutput and alwaysOutputData: true — downstream 5xx becomes a green run that still writes state. This is the exact trap behind the 13-burned-touches incident in the community thread.

F zombie

Active scheduled workflow with no executions in the window at all.

Run it in 30 seconds

curl -sSL https://raw.githubusercontent.com/auroraxo/greenscan/v0.1.0/greenscan.py \
  -o greenscan.py

export N8N_API_KEY="n8n_api_xxx"    # Settings → n8n API
python3 greenscan.py --base-url https://n8n.example.com

Exit code 1 means findings. --json for machines, --dry-run for a demo without an instance, --days N to widen the window. Python ≥ 3.8, zero non-stdlib dependencies.

What it is — and what it isn't

  • Is: a free, read-only, one-shot audit. No account, no signup, no telemetry. The API key never leaves your machine and is never written to disk.
  • Isn't: a monitor, an alerter, or an outcome verifier. It cannot tell you whether WhatsApp actually delivered or Stripe actually settled — it reads n8n's API and nothing else.
  • Won't: modify your instance, install nodes, or change settings. workflow:read + execution:read scopes are enough (Enterprise scoped keys).

If the report comes back empty, you didn't need a paid monitor yet. If it flags coaf_risk on your production cadence, you now know exactly what you'd be buying.

Why this exists

Built after reading two threads where n8n operators priced their own pain: community.n8n.io/t/310860 (a WhatsApp cadence where 13 touches were burned by HTTP 500s routed through continueRegularOutput) and community.n8n.io/t/316526 (cost and detection time). Watchflow, Midwatch and OutcomeGuard already sell continuous monitoring at $19–$99/mo and they're the right tool if you need alerts. greenscan is the step before that: find out in 30 seconds whether you have the problem at all.
